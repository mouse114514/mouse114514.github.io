第三课

进程、窗口与消息机制

系统底层是如何运行的？

程序 vs 进程

很多人分不清程序和进程，其实很简单：

  • 程序 = 硬盘上的一个文件（.exe），是静态的
  • 进程 = 程序被加载到内存开始运行后的"实例"，是动态的

打开记事本 → 系统创建一个 notepad.exe 进程。关掉它 → 进程销毁。

你打开同一个程序三次 → 有三个独立的进程，互不干扰。

进程的组成

一个进程在系统里包含：

  • PID（进程 ID）—— 系统的唯一编号，每个进程一个
  • 虚拟地址空间 —— 每个进程以为自己独占 4GB（32位）/ 8TB（64位）内存
  • 句柄表（Handle Table）—— 记录进程打开的资源（文件、窗口等）
  • 线程 —— 进程至少有一个线程，真正的执行单元
按 Ctrl + Shift + Esc 打开任务管理器，看"详细信息"标签，里面每一行就是一个进程。

窗口的本质

在 Windows 里，窗口就是一个数据结构（由系统管理），不是屏幕上画出来的图片。

  • 每个窗口有一个 HWND（窗口句柄）—— 窗口的"身份证号"
  • 系统维护 Z 序（Z-Order）—— 窗口的堆叠层次
  • 窗口属于某个进程，进程可以创建多个窗口

消息队列

Windows 是一个消息驱动的操作系统。一切皆消息：

  • 鼠标点击 → WM_LBUTTONDOWN 消息
  • 按键按下 → WM_KEYDOWN 消息
  • 窗口需要重绘 → WM_PAINT 消息

每个线程（有窗口的）都有自己的一条消息队列。系统把消息投递到对应线程的队列中，线程不断取消息、处理、再取——这就是消息循环（Message Loop）。

为什么程序会"卡死"？

卡死的本质是消息循环被阻塞了：

  • 程序忙着做一件耗时的事（如读取大文件、死循环）
  • 没有回到消息循环取消息
  • 队列里的消息越积越多
  • 系统检测到该窗口长时间没处理消息 → 标题栏出现"无响应"
任务管理器结束进程，就是强制杀掉它的消息循环。

Z 序与顶层窗口

窗口的 Z 序决定了谁在谁上面：

  • TopMost 窗口始终在最上层（如任务管理器"总是置顶"）
  • 前台窗口（Foreground Window）是 Z 序顶层的那个
  • 后台窗口被前台窗口覆盖，收不到鼠标点击
  • 设置窗口为 TopMost 使用 Ctrl + 鼠标点任务管理器左下角的"选项→总在最前"

总结

  • 程序是文件，进程是运行中的实例，有 PID
  • 窗口是系统管理的数据结构，由 HWND 标识
  • 所有输入通过消息队列传递，系统靠消息驱动
  • 卡死 = 消息循环被阻塞，不再处理新消息
  • Z 序决定窗口前后层次
