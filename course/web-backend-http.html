HTTP 协议基础

浏览器和服务器是怎么聊天的/div>

HTTP 是什么？

HTTP（超文本传输协议）是浏览器和服务器之问strong>沟通的语言、/p>

  • 你打开网页 ↀ浏览器用 HTTP 向服务器"要数据
  • 服务器收到请汀ↀ用HTTP 返回网页内容
  • 每次访问网页，都是一欀HTTP 请求-响应

请求方法

最常用的两个：

GET —从服务器获取数据

   访问网页、看图片、搜紀ↀ都是 GET

POST —向服务器发送数据/p>

   登录、注册、提交表单ↀ都是 POST

其他还有：PUT（更新）、DELETE（删除）、PATCH（修改部分）

URL 的结析/h2>

https://www.example.com:443/path/page?id=1#section

  • https:// —协议
  • www.example.com —域名
  • :443 —端口号（https 默认 443，http 默认 80！/li>
  • /path/page —路径
  • ?id=1 —查询参数
  • #section —锚点（页面内位置！/li>

状态码

服务器用状态码告诉浏览器结果：

  • 200 OK —成功，网页正常返回/li>
  • 301/302 —重定向（跳转到另一个地址！/li>
  • 404 Not Found —找不到页静/li>
  • 500 Internal Server Error —服务器内部错试/li>
持F12 ↀNetwork 标签 ↀ刷新页面，能看到每个请求的状态码、/div>

请求和响应头

HTTP 消息除了"正文"，还有头信恀（Headers）：

请求头（Request Headers！/strong>！/p>

  • User-Agent —浏览器信恀/li>
  • Cookie —登录状态/li>

响应头（Response Headers！/strong>！/p>

  • Content-Type —返回内容的类型（text/html, application/json！/li>
  • Set-Cookie —让浏览器保存 Cookie

HTTP 是无状态的

HTTP 每次请求都是独立的，服务器不记得你之前做过什么、/p>

  • 第一次请求：你是谁？
  • 第二次请求：又是谁？
所以需要Cookie 和Session 来解内记住登录状态的问题。服务器给浏览器发一一身份试（Cookie），下次请求时浏览器带上它、/div>

总结

  • HTTP = 浏览器和服务器通信的协设/li>
  • GET 请求数据，POST 提交数据
  • URL = 协议 + 域名 + 路径 + 参数
  • 状态码！00 成功、04 找不到、00 服务器错试/li>
  • Headers 传递附加信息（Cookie、Content-Type！/li>
  • HTTP 无状态，用Cookie/Session 记忆身份
