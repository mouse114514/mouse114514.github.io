网络通信原理

打开一个网页背后发生了什么？

网络的四层模型

网络通信是分层处理的，每一层只关心自己的事：

  • 应用层 — 你用的软件（HTTP / DNS / SMTP）
  • 传输层 — 确保数据可靠到达（TCP / UDP）
  • 网络层 — 路由和寻址（IP）
  • 链路层 — 物理传输（以太网 / Wi-Fi）

上层的数据被封装进下层的"包裹"里，一层套一层，像俄罗斯套娃。

IP 地址

每台联网设备有一个 IP 地址，像网络门牌号。

  • IPv4 — 32 位，如 192.168.1.1，约 43 亿个
  • IPv6 — 128 位，解决 IPv4 不够用的问题
  • 公网 IP — 全球唯一，可直接从互联网访问
  • 内网 IP — 如 192.168.x.x，只在局域网内有效
命令提示符输入 ipconfig 查看本机 IP。

DNS：电话簿

你记不住 IP 地址，所以用域名（baidu.com）。DNS 就是"电话簿"：

  • 你输入 www.baidu.com
  • 系统找 DNS 服务器查这个域名对应哪个 IP
  • DNS 返回 IP（如 183.232.231.172）
  • 浏览器再用这个 IP 去连接服务器
查询顺序：浏览器缓存 → 系统缓存 → 路由器缓存 → ISP 的 DNS → 根 DNS → 顶级域 → 权威 DNS

试试 nslookup baidu.com

TCP 三次握手

TCP 是面向连接的协议，传数据前要先建立连接：

  • SYN — 客户端 → 服务器："我要连你"
  • SYN-ACK — 服务器 → 客户端："好的，我准备好了"
  • ACK — 客户端 → 服务器："收到，开始传数据"

这就是"三次握手"。目的是确认双方的发送和接收能力都正常。

端口（Port）

IP 地址找到设备，端口找到设备上的具体程序：

  • 一个连接由五元组唯一标识：(源IP, 源端口, 目标IP, 目标端口, 协议)
  • Web 服务默认用 80（HTTP）或 443（HTTPS）
  • DNS 用 53，SSH 用 22，远程桌面用 3389
用 netstat -ano 查看当前系统所有的网络连接和监听端口。

打开网页的全过程

你在地址栏输入 www.baidu.com：

  • 浏览器查缓存（有就直接用）
  • DNS 解析 → 拿到 IP 地址
  • TCP 三次握手建立连接
  • 发送 HTTP GET 请求
  • 服务器返回 HTML 页面
  • 浏览器发现页面里还有 CSS、JS、图片
  • 重复以上步骤下载所有资源
  • 渲染引擎把这些拼成一个完整页面

总结

  • 网络分层处理，每层关注自己的事
  • IP 是设备地址，DNS 把域名翻译成 IP
  • TCP 三次握手建立可靠连接
  • 端口号区分同一设备上的不同程序
  • 打开网页 = DNS + TCP + HTTP + 渲染
按 F12 打开浏览器开发者工具 → 网络标签，能看到每个请求的全过程。
