RESTful API 设计

前后端分离的接口规范

什么是 REST？

REST（表述性状态传递）是一套 API 设计规范：

  • 把数据视为"资源"（Resource）
  • 用 HTTP 方法操作资源
  • 返回 JSON 格式数据
  • 无状态（服务器不保存客户端状态）

URL 设计规范

资源用名词复数：

  • GET /api/posts — 获取文章列表
  • GET /api/posts/1 — 获取单篇文章
  • POST /api/posts — 创建文章
  • PUT /api/posts/1 — 更新文章
  • DELETE /api/posts/1 — 删除文章
URL 里不用动词（不要 /getPosts 或 /createPost），用 HTTP 方法表达操作。

Flask 实现 RESTful

@app.route("/api/posts", methods=["GET"])

def get_posts():

    posts = Post.query.all()

    return jsonify([{"id": p.id, "title": p.title} for p in posts])

@app.route("/api/posts", methods=["POST"])

状态码

  • 200 — GET 成功
  • 201 — POST 创建成功
  • 204 — DELETE 成功（无返回内容）
  • 400 — 请求参数错误
  • 401 — 未认证
  • 403 — 没有权限
  • 404 — 资源不存在
  • 500 — 服务器内部错误

错误处理

统一返回 JSON 错误：

@app.errorhandler(404)

def not_found(e):

    return jsonify({"error": "资源不存在"}), 404

 

@app.errorhandler(400)

def bad_request(e):

    return jsonify({"error": "请求参数错误"}), 400

Postman 测试 API

Postman 是测试 API 的常用工具：

  • 选择 GET/POST/PUT/DELETE
  • 输入 URL
  • Body → raw → JSON 输入参数
  • 点 Send 查看返回结果
也可以直接用 curl 命令测试：curl -X GET http://localhost:5000/api/posts

总结

  • REST = 用 HTTP 方法操作资源，返回 JSON
  • GET 查 / POST 增 / PUT 改 / DELETE 删
  • URL 用名词复数，不用动词
  • 状态码正确表达结果（201 创建、404 未找到）
  • request.get_json() 获取请求体 JSON
  • jsonify() 返回 JSON 响应
